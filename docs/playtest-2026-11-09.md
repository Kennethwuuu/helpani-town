## 测试发现并修复的问题

| 问题 | 修复 |
| --- | --- |
| 低台导航直接走向平台中心，和斜坡画面不一致，上下坡脚掌穿入最高约 37/32 像素 | 增加坡顶节点，斜坡与导航共用几何；坡顶后沿水平平台前进，转接处按各着地脚的实际支撑面修正，摆动腿与身体动作保留 |
| 高台入口有一段横向路线没有可见支撑 | 添加与落点相连的水平踏板，覆盖原来的空隙 |
| 使用中移动设施，坡顶或离台转接可能提前生效 | 将坡顶、斜坡、平台进出路径纳入占用判定，抵达安全节点后再应用布局 |
| 布置已在画面生效，但断网导致生效确认/首次观察失败，此后永久漏传 | 保留待确认记录，按生效→观察顺序补传；传输重试保留 UUID，版本冲突读取新状态后重建操作；联网、回到前台和重新激活时继续同步 |
| 巡护初读或两次响应丢失后界面停在旧状态 | 联网/返回前台读取已提交状态；重试与读取不重复结算事件 |
| 选择已保存，之后读取林地库存失败，界面却提示整个选择失败；断网点击回林地抛出异常 | 分别提示巡护已保存和库存待同步；断网仍可返回已打开的林地，无未处理的页面异常 |

入口及三个浏览器模块已统一更新资源版本，避免已有页面继续加载旧模块。

浏览器脚本由 Playwright CLI 的 `run-code --filename` 执行，不增加生产浏览器依赖。用独立数据库在 3110 端口启动后，按场景使用全新浏览器会话：

- `tools/browser/new-player-gate.js`：首页开始的完整双关与摄影闭环。
- `tools/browser/contact-review.js`：导航、支撑和逐帧接触；`contact-pending-review.js`：四组设施占用调整。
- `tools/browser/recovery-gate.js`：网络故障、响应丢失、离线相册与巡护恢复。
- `tools/browser/mobile-gate.js` 配合 `mobile-emulation.config.json`：真实触摸事件仿真。

部分浏览器导航等待 `load` 事件曾超时，但页面 `readyState=complete` 且本地 API 正常。脚本已改为等待 `DOMContentLoaded` 后检查游戏就绪；最终完整流程通过，不把工具的加载等待超时报告成已确认的产品故障。

## 剩余边界与下一优先事项

1. iOS Safari、真实 iPhone/iPad 和低端手机尚未验收。本机没有可用的已连接 iOS 设备，也没有进行游戏的 Safari/WebKit 验证；手机仿真不能替代它们。
2. 自动补传队列保留在当前页面内存中。断网期间关闭页面，尚未提交的新观察没有离线持久化保证；已经提交的布局、巡护和奖励继续由 SQLite 恢复。刷新后的动物仍从安全落点开始。
3. 当前为程序绘制的风格化动物，步态和支撑检查没有实现完整骨骼或物理系统；头部造型保留用户接受的版本。写实毛发、肌肉和真实声场仍未实现。
4. 自动化证明流程可完成，尚未证明真实初访玩家能无提示理解流程或愿意再次来访。下一步先做 iOS 真机摄影/存储测试和首次玩家观察，再决定更多设施与账号同步。
5. 远端 PayPal Sandbox 授权捕获与 Astropods 实际生成仍未联调，不在本轮通过范围。
