## 3. 测试环境与证据

### 隔离方式

保持玩家正在使用的 `localhost:3000`、`data/helpani.sqlite` 和浏览器相册不变。破坏性 fixture、清空 Cookie/IndexedDB、数据库改造及故障注入只在独立测试环境执行。测试浏览器使用独立上下文。

建议分配：玩法 `127.0.0.1:3117`，支付 `127.0.0.1:3118`，AI `127.0.0.1:3119`；三个进程各用自己的临时 SQLite。整个测试会话固定同一原点，不混用 `localhost` 和 `127.0.0.1`。

Node.js 需要 22.13 或更高版本。先记录源码版本；当前若还没有提交，使用源码文件哈希作为基线。不默认重跑 `npm ci` 或 73 项 `npm test`。只有新增用例、相关业务修改或未解决失败才运行受影响测试；改动影响公共状态/存储、无法缩小范围时才做全量回归。REL-01 的干净环境仍需按交付说明独立安装与启动。

玩法服务示例，在项目根目录执行：

```bash
mkdir -p /private/tmp/helpani-qa-20261111
HOST=127.0.0.1 PORT=3117 PUBLIC_ORIGIN=http://127.0.0.1:3117 \
DB_PATH=/private/tmp/helpani-qa-20261111/game.sqlite \
PAYPAL_CLIENT_ID= PAYPAL_CLIENT_SECRET= \
ASTRO_GATEWAY_URL= ASTRO_GATEWAY_API_KEY= npm start
```

支付测试改用端口 3118 和 `paypal.sqlite`，不设置上述两个空 PayPal 变量，由启动脚本从私有 `.env` 读取已有 Sandbox 凭据；AI 变量仍置空。AI 测试改用端口 3119 和 `ai.sqlite`，仅 PayPal 变量置空，由 `.env` 读取已准备的 Astropods 配置。

测试 agent 可读取配置是否齐全、在进程内使用凭据；报告、截图和录屏不包含密钥、访问令牌、会话 Cookie 或登录密码。买家授权由用户在能看到的测试窗口完成，测试 agent 随后查询结果。拿不到凭据或需要设备时标 `BLOCKED` 并一次列清依赖，继续独立用例。

### 记录格式

每个用例记录：用例 ID、源码基线、环境与尺寸、测试方式、前置状态、操作、预期、实际、状态及证据路径。涉及积分/付款/奖励时保存脱敏的前后状态，涉及动画记录触发动作和状态变化，涉及照片保存实际下载文件与哈希。

- 状态用 `PASS / FAIL / BLOCKED / NOT_RUN / FLAKY / COVERED`。`COVERED` 表示复用已有证据，单独统计，不计为本次新测 PASS。明确标识 `LIVE_SANDBOX / LIVE_ASTROPODS / MOCK / BROWSER / REAL_DEVICE`，允许一个用例同时具有多个方式。
- `MOCK` 通过不能填作真实服务通过；`BROWSER` 通过不能填作真机通过。
- 保留首轮失败日志。超时后重试通过，仍记录首次失败与复测结果；定位为环境抖动或修复后再给最终结论，不靠放宽断言或全局超时掩盖问题。
- 录屏和日志放在 `output/qa-2026-11-11/`，最终脱敏报告放 `docs/qa-report-2026-11-11.md`。`output/` 被 Git 忽略，需公开的精选证据应另行纳入交付，不能让评委依赖本机文件。
