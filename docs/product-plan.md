## 产品目标和首发范围

让喜欢野生动物的人拥有一个愿意反复探望的动物生活空间。动物在符合物种习性的救助中心或自然栖地中自主活动，玩家通过照护、栖地布置、观察收集和拍照逐渐认识它，形成长期养成与自愿分享的理由。真实机构的照片、文字、视频和执行记录，持续说明现实保护工作如何推进。

游戏核心循环为 **探望与观察 → 照护或布置 → 动物自主反馈 → 拍照与共同经历 → 解锁新的生活细节 → 再次探望**。首个体验小样采用一只小熊猫和一个精细林地场景，验证动物表现力、养成反馈和拍照意愿后扩展。玩家也可自主选择参加身边的保护活动，或支持具体项目；每次真实参与保留确认方、时间和进展记录。

环境布置确定为核心养成：每项重要设施要带来可使用的生活空间或新的活动路线。首轮做一件休息平台和两个有效位置，验证“选择位置 → 保存布置 → 动物自主使用 → 拍照留念”；后续由观察、照护与巡护章节稳定解锁新的布置内容。交互和验收见 [环境布置规格](animal-life-experience.md#环境布置作为核心养成)。

配套探索循环为 **掷骰 → 沿格子路线前进 → 事件选择 → 获得见闻、故事或勋章 → 解锁新的观察内容 → 回小镇探望**。地图上的巡护标记与栖地中自主活动的动物分别表现；随机额外发现与确定的路线里程碑共同推进收藏。

首个真实公益试点按 **Web、一个城市、一家合作机构、一场真实的野生动物保护活动** 规划。动物生活小样先验证游戏体验，报名与核验验证真实参与，项目进展让支持者看到后续。真实支付和物资履约在单地区、单币种下单独验收。更多城市、物种、机构自助入驻、跨境募捐和自动拨付列入后续候选范围。

现有原型已实现绿海龟、小熊猫和中华穿山甲的领养照护、两项上海虚构活动、会话内模拟核验和积分、模拟赞助预留、支持记录、AG Grid 核验台与 Postman 集合。PayPal Sandbox 已完成捐助及指定物资付款的授权、捕获和账本核对，Astropods 已完成两种资料选择的真实生成与人工核对。生成任务仍为组织方审阅草稿，对应答题或地图任务的发布执行尚未实现。上海、组织、活动、预算和项目进展均为演示样例。 [黑客松 MVP](mvp.md) · [运行与配置](../README.md)

## 角色与核心体验

| 角色 | 最先要解决的问题 | 完成后看到的结果 |
| --- | --- | --- |
| 玩家 | 这只动物在做什么？我的照护和布置会带来什么变化，有值得拍下的瞬间吗？ | 自主活动的伙伴、逐步成长的栖地、观察册、成长故事和可保存分享的照片；新增体验见专项规格 |
| 志愿者 | 附近有什么活动？我报名或参加后，怎么确认完成？ | 报名结果、到场核验状态、积分到账记录 |
| 项目支持者 | 我能支持哪一项具体需求？出资后进展到哪里了？ | 订单回执、资金状态、物资状态和带来源的项目更新 |
| 活动组织方 | 如何管报名、核验到场、纠正错发？ | 本机构报名清单、核验操作和可追溯的纠错记录 |
| 救助机构 | 如何清楚地说明项目需求、预算和成果？ | 可审核的项目资料、物资清单、进展证据和任务草稿 |
| 平台运营 | 如何审核合作方、处理积分与资金差异，并决定是否扩大范围？ | 审核记录、差异队列、对账结果和试点数据 |

玩家可以独立走三条路径。**动物生活与养成**通过照护、环境布置、观察、巡护和摄影获得虚拟成长与共同经历，本轮以小熊猫生活场景连接原有领养、喂食与手记；**公益活动**通过报名、到场和组织方核验获得公益积分；**直接支持**从项目或指定物资进入结账，再回项目看进展。拍照与分享属于虚拟游戏体验，公益积分继续由活动核验产生。积分兑换和直接支持各自保留来源和状态。

玩家端分为小镇、附近活动、救助项目和我的参与；新的小镇主体验以动物生活场景为中心，连接巡护路线、观察册、摄影与项目日记。组织方工作台分为活动与报名、项目与证据、任务草稿。平台运营负责合作方审核、纠错和对账。真实公益试点可沿用现有页面验证核验与状态回传，新增游戏体验按小样单独验收。

## 版本、工期和验收关口

原有时长按一人全职开发、Web 优先、现有公益链路从当前原型起算，不包含本轮游戏小样及后续更多美术、动物行为、分享和地图内容。本轮已选定 2.5D 程序绘制路线，公开版本与内容扩展应据试玩和资产需求重新估算。合作沟通、数据授权和生产收款开通会影响日历时间，可与研发并行准备。真实试点以合作与数据条件为准，可独立于参赛结果推进。

## 开发顺序和交付物

1. **范围与设计**。游戏线先用一个场景确认动物动作、空间与镜头的表现目标，再做自主行为、环境反馈、少量养成和摄影。公益线继续写报名核验、支持回执和异常处理的验收用例，用一场活动和一个项目走通玩家端与机构端。
2. **并行开发**。玩法线先交付 S 的动物生活小样，再连接 E 的巡护地图、选择事件与收藏，并扩展跨日进度；组织方线处理账号、权限、报名、核验及现场媒体更新；集成线处理 Astropods、PayPal、发布和评委环境。真实试点同时推进机构沟通和资料授权。
3. **联调与发布**。以浏览器演练完整流程，用 Postman 覆盖金额篡改、未知回跳和核验去重。参赛版记录实际模型与沙箱验收结果。真实试点再补账号隔离、纠错、数据备份恢复和运营手册。正式资金版增加退款、对账和履约验证。
4. **观察与迭代**。试点后按真实参与数据和用户反馈调整玩法与活动入口。发生积分错发、隐私投诉或支付对账差异时，先暂停受影响入口，再处理、复测和恢复。

4–6 周试点可按四步排期。第 1 周定合作活动、权限和证据格式；第 2–3 周做正式账号、组织方与报名核验；第 4 周跑通积分、纠错和项目进展；第 5–6 周用于上线演练、邀请用户和试点修复。机构负责人确认活动和证据，平台运营负责审核与异常，开发负责人负责实现和发布。

## 首轮怎么衡量

动物生活小样先观察玩家是否愿意自由停留、能否记住个体习惯、是否主动保存或分享照片，以及下次想回来看的内容。结合后续复访确认期待是否得到回应。以下原有指标继续用于参赛和公益链路，新增游戏体验的记录方案在小样可玩后单独确定。

| 指标 | 口径 |
| --- | --- |
| 首喂完成率 | 完成首次喂食的领养用户 ÷ 新领养用户。观察哪些人卡在领取粮或喂食入口。 |
| 次日照护回访率 | 首喂用户中，在下一个北京时间自然日完成照护的比例。 |
| 活动报名率 | 查看活动详情后完成报名的独立用户 ÷ 详情独立访客。 |
| 报名到核验率 | 活动结束后已核验的独立报名 ÷ 有效报名，取消和未到场单列。 |
| 积分与资金准确性 | 检查重复积分、跨机构越权、预算超额、支付与回执差异。出现异常时按版本验收条件处理。 |
| AI 草稿可核对率 | 抽查草稿中关键陈述是否有可回查资料支持，记录需人工修改的原因。 |

动物生活小样区分引导拍照和自由阶段的主动拍摄、导出，先验证观察兴趣与回访期待；实际社媒传播另验。公益链路按试玩、真实试点和真实资金分开记录，真实公益试点的核心证据是一条可查的完整链路：一位用户从领养走到报名与到场，由合作机构完成核验，最终在小镇看到一次正确的积分入账。
